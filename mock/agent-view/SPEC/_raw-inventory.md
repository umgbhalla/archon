## 1. Session State (icon color / animation / meaning)

From the state table (L109-116). Each row starts with an icon whose **color and animation** show state (L107):

| State       | Icon shows as | What it means (verbatim) |
| :---------- | :------------ | :----------------------- |
| Working     | Animated      | Claude is actively running tools or generating a response |
| Needs input | Yellow        | Claude is waiting on a specific question or permission decision from you |
| Idle        | Dimmed        | The session has nothing to do and is ready for your next prompt |
| Completed   | Green         | The task finished successfully |
| Failed      | Red           | The task ended with an error |
| Stopped     | Grey          | The session was stopped with `Ctrl+X` or `claude stop` |

Notes:
- "Working" is conveyed by **animation** (animated icon), not a static color (L111).
- Sessions show as **Failed** (red) after machine shutdown; attach/peek/reply restarts them (L132, L515-519).

## 2. Process-shape icons (separate axis from state)

"Separately, the icon's **shape** shows whether the underlying process is running" (L118). Table (L120-124):

| Shape | What it means (verbatim) |
| :---- | :----------------------- |
| `✻` or animated `✽` | The session process is alive and replies immediately |
| `∙` | The process has exited. You can still peek, reply, or attach, and Claude restarts from where it left off |
| `✢` | A `/loop` session sleeping between iterations. The row shows its run count and a countdown |

So two icon dimensions combine: **color/animation = state**, **shape = process liveness**.
- `✻` static alive, `✽` animated alive (actively working).
- `∙` process exited (still usable).
- `✢` `/loop` sleeping; row shows run count + countdown (e.g. `run 12 · all checkpoints cleared … in 4m` in sample, L97).

## 3. Groups (and rules for which group a session falls in)

Sessions are **grouped by state**, ones that need input at top (L73, L188). Group order top→bottom (L189): `Ready for review` and `Needs input` above `Working` and `Completed`. Pinned sessions and the ones that need you are at the top (L73).

Groups seen in sample table (L85-103): **Pinned**, **Ready for review**, **Needs input**, **Working**, **Completed**, plus the `… N more` fold row.

Group membership rules (verbatim notes, L189-202):
- Group names **do not map one-to-one** to states (L189).
- **Ready for review**: a session moves here "when it has an open pull request" (L189).
- **Completed** group: "collects finished, failed, and stopped sessions together" (L189). I.e. Completed group = Completed + Failed + Stopped states.
- **Pinned**: sessions pinned with `Ctrl+T` (pins to top, keeps process running while idle) (L193).
- **Needs input**: sessions in the Needs input state.
- **Working**: sessions in the Working state.
- **`… N more`**: "Older completed sessions fold into a `… N more` row to keep the list short. Failures and sessions with an open pull request always stay visible." (L202).

Grouping toggle: `Ctrl+S` groups **by directory** instead of by state; choice persists across runs (L189, L228). When grouped by directory, the highlighted row's directory becomes the dispatch target (L273).

Group header behaviors:
- `Enter` on a group header collapses it (L196).
- `Ctrl+X` on a group header deletes every session in that group after confirmation (L198).

## 4. UI Regions

### Header (L11 alt-text, L376)
- **Version**: "Claude Code v2.1.140" (L11 alt-text).
- **Model**: the dispatch default; new sessions use this model; comes from `model` setting; overridable with `--model` on `claude agents` (L11, L376).
- **Working directory (cwd)** (L11).
- **Summary count** (L11).
- The model name shown in the header is the dispatch default (L376).

### Tab title behavior (L128)
- Shows awaiting-input count while agent view is open.
- `2 awaiting input · claude agents` when sessions need input.
- `claude agents` when none do.

### Row anatomy
- Each row shows: session's **name**, **current activity (summary)**, and **how long ago it last changed** (time-ago) (L73). Also "current activity, and how long ago it last changed."
- **Summary** (L134-140): one-line, generated by a Haiku-class model. Tells what the session is doing / needs / produced without opening transcript. While actively working, refreshes at most once every 15 seconds, plus once when each turn ends.
  - From v2.1.161: when running 2+ parallel work items (subagents, background shell commands, monitors), a `done/total` count such as `2/5` appears **before** the summary text (L138).
- **Time-ago**: appears at right (sample shows `3m`, `2h`, `1m`, `2m`, `in 4m`, `9m`, `4h`) (L87-101).
- **PR label** (L126, L142-157): `PR #N` label at the **right edge** of a row = the pull request the session opened (not part of state icon). Linked to the PR in terminals that support hyperlinks. Persists when you send a follow-up (PR stays visible while row reverts to live progress). When >1 PR opened, label shows a count such as `3 PRs`, colored by the open PR that most needs attention; open peek panel to see them all.
  - **PR color states** (L148-156):

    | Color  | Pull request status (verbatim) |
    | :----- | :----------------------------- |
    | Yellow | Waiting on checks or review, or checks failed |
    | Green  | Checks passed and no review is blocking |
    | Purple | Merged |
    | Grey   | Draft or closed |

  - "review and merge the pull request when its number turns green" (L157).

### Dispatch input (L11, L45, L206, L242, L412)
- Input at the bottom of agent view (L11, L45).
- Type prompt + `Enter` to dispatch a new background session (L242).
- Typing also used to **filter** instead of dispatching (L206).
- Paste an image into the prompt to include a screenshot/diagram (L245).
- Prompt shorter than four characters rejected with `Too short` hint (L513).

### Footer (L11, L412)
- Footer of keyboard hints (L11 alt-text).
- The active defaults (permission mode, model, effort) appear in the **footer below the dispatch input** (L412).

## 5. Modes / Overlays

- **Table view** (default): grouped session list (L72-103).
- **Peek panel**: opened with `Space` on a selected row (L57, L160). Closed with `Esc` or `Space` (L222, L233). See section 7.
- **Attached session**: full interactive Claude Code session, fullscreen (L60-62, L172-183). See section 8.
- **Help (`?`)**: "Press `?` in agent view to see every shortcut in context" (L216, L235).
- **Rename**: `Ctrl+R` to rename the selected session (L195, L229).
- **Delete-confirm**: `Ctrl+X` stops; `Ctrl+X` again within two seconds deletes (L198, L231). On a group header, deletes every session in the group **after confirmation** (L198).
- **Group-by toggle**: `Ctrl+S` switches grouping between state and directory; persists across runs (L189, L228).
- **Filter mode**: typing `a:`, `s:`, or `#`/PR URL in dispatch input filters instead of dispatching (L206-212). See section 6.
- **Onboarding-empty**: before first session dispatched, agent view shows a short onboarding hint with example prompts in place of the session list (L505). Also: a single empty `←`-created row shows an onboarding hint below it (L185).

## 6. Dispatch prefixes / mentions / filters

### Dispatch prefixes & mentions (L249-257)

| Input (verbatim) | Effect (verbatim) |
| :--------------- | :---------------- |
| `<agent-name> <prompt>` | If the first word matches a custom subagent name, that subagent runs as the session's main agent with the configuration from its frontmatter |
| `@<agent-name>` | Mention a custom subagent anywhere in the prompt to run it as the main agent |
| `@<repo>` | Mention a repository under the directory you opened agent view from to run the session there |
| `/<command>` | Suggest skills and commands to dispatch as the prompt |
| `! <command>` | Run a shell command as a background job instead of starting a Claude session. The job appears as a row you can attach to, watch, and detach from |
| `#<number>` or a pull request URL | If a session is already working on that PR, select it instead of dispatching |
| `Shift+Enter` | Dispatch and immediately attach to the new session |

Precedence/notes (L259-263):
- `/exit` and `/quit` close agent view; `/logout` signs you out. Every other command/skill is sent to a new background session as its first prompt (L259).
- When the same `@name` matches both a subagent and a sibling repo, the subagent takes precedence (L263). Bare first-word match also applies; use `@` to be explicit (L263).

### `! bash` dispatch (L324-340)
- Type `!` as the first character; `!` shows as a prefix; everything after is the command (L326).
- Example: `! pytest -x` (L329). Shell equivalent: `claude --bg --exec 'pytest -x'` (L335).
- Runs as a PTY-backed job, appears as a row with most recent line of output as status (L338). No model invoked, output not sent to any session (L338).
- Output stays in memory, not on disk; row + output clean up ~5 min after the command exits (L340).

### Filters (typing in dispatch input filters instead of dispatching) (L208-212)

| Filter (verbatim) | Shows (verbatim) |
| :---------------- | :--------------- |
| `a:<name>` | Sessions running the named agent |
| `s:<state>` | Sessions in the given state, such as `s:working`. Also accepts `s:blocked` for everything waiting on you |
| `#<number>` or a PR URL | The session working on that pull request |

## 7. Keyboard shortcuts (full table)

"Press `?` in agent view to see every shortcut in context." (L216). Full table (L218-235):

| Shortcut (verbatim) | Action (verbatim) |
| :------------------ | :---------------- |
| `↑` / `↓` | Move between rows |
| `Enter` | Attach to the selected session, or dispatch if there's text in the input |
| `Space` | Open or close the peek panel for the selected session |
| `Shift+Enter` | Dispatch and attach immediately |
| `→` | Attach to the selected session |
| `Alt+1`..`Alt+9` | Attach to session 1–9 in the focused session's directory |
| `Tab` | On an empty input, browse all subagents. Otherwise apply the highlighted suggestion |
| `Ctrl+S` | Switch grouping between state and directory |
| `Ctrl+T` | Pin or unpin the selected session |
| `Ctrl+R` | Rename the selected session |
| `Ctrl+G` | Open the dispatch prompt in your `$VISUAL` or `$EDITOR` |
| `Ctrl+X` | Stop the session; press again within two seconds to delete it |
| `Shift+↑` / `Shift+↓` | Reorder the selected session |
| `Esc` | Close the peek panel, clear the input, or exit |
| `Ctrl+C` | Clear the input; press twice to exit |
| `?` | Show all shortcuts |

Additional context-specific shortcuts mentioned in prose (not in the table):
- `Enter` on a **group header** collapses it (L196).
- `Ctrl+X` on a **group header** deletes every session in that group after confirmation (L198).
- `←` on an empty prompt: detach / background current session + open agent view (L61, L65, L179, L185). Toggle off via `/config` `leftArrowOpensAgents` setting (L185).
- `Ctrl+Z`: detach immediately when a dialog has focus and isn't responding to `←` (L179, L183).
- Peek-panel navigation: `↑`/`↓` peek adjacent sessions without closing the panel; `→` attaches (L169).
- Peek multiple-choice: press a **number key** to pick an option (L165).
- Peek: `Tab` fills input with a suggested reply you can edit (L165).

## 8. Peek panel behaviors (L57, L160-169)

- Open with `Space` on selected row (L57, L160).
- Shows: what the session needs from you, its **most recent output**, and any PRs it opened (L57, L161). It shows recent output **or** the question it's waiting on, **not** the full transcript (L57).
- From v2.1.161: when running parallel work items, panel names the **longest-running** one and how long it's been going (L163).
- Type a reply + `Enter` to send to that session (L57, L165).
- **Multiple-choice question**: panel shows options; press a **number key** to pick one (L165).
- **Other blocked sessions**: press `Tab` to fill input with a **suggested reply** you can edit before sending (L165).
- **`!` bash in reply**: prefix a reply with `!` to send a Bash command instead (L165).
- Voice dictation (v2.1.145+): hold/tap push-to-talk while reply input focused to dictate (L167). Same in the bottom dispatch input.
- **Adjacent peek**: `↑`/`↓` peek adjacent sessions without closing the panel; `→` to attach (L169).

## 9. Attach / detach behaviors (L60-62, L172-183)

- Attach: `Enter` or `→` on a selected row (L60, L172). Agent view replaced by full interactive session.
- **Recap**: on attach, Claude posts a short recap of what happened while you were away (L173).
- While attached, every command, shortcut, and feature works like any session (L175).
- **Fullscreen**: attached sessions always render in fullscreen mode regardless of `tui` setting (background session has no scrollback) (L177).
- Scroll with `PgUp`, `PgDn`, or mouse wheel (L177).
- `Ctrl+O` for **transcript mode** (L177).
- Native scroll / tmux copy mode show only current viewport (L177).
- **Detach**: `←` on an empty prompt detaches and returns to agent view (L62, L179).
- If a dialog has focus and isn't responding to `←`, press `Ctrl+Z` to detach immediately (L179).
- **`Ctrl+C` rules** (L181-183): keeps standard interrupt behavior while attached — cancels a running response or `!` shell command rather than detaching. `Ctrl+C` **twice** on an empty prompt detaches (same as any session).
- Detaching never stops a background session: `←`, `Ctrl+Z`, `/exit`, double `Ctrl+C`, double `Ctrl+D` all leave it running (L183). To end a session from inside it, run `/stop` (L183).
- `←` on empty prompt works from any session (not only attached ones): backgrounds current session + opens agent view with that row selected (L185). Row created even from fresh session with no history, so `→` returns to it (L185).

## 10. Turn off agent view (L491-493)

- Set `disableAgentView` setting to `true`, OR
- Set `CLAUDE_CODE_DISABLE_AGENT_VIEW` environment variable.
- Administrators can enforce via managed settings (L493).
